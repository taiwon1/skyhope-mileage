# SkyHope 실제 사용 흐름 검증 — 2026-09-15

## 실행 환경과 결과

- Windows / Microsoft Edge headless / Playwright, 실제 index.html과 ES Modules 실행.
- Firestore SDK만 메모리 저장소로 교체하고 그 외 외부 요청을 차단. 운영 DB 변경 없음.
- 기존 test.html 40개 통과. 문서의 73개와 달리 현재 파일에는 40개 테스트가 있음.
- 통합 실행 33개 시나리오 통과, 실패 0, 브라우저 JavaScript 오류 0. 33개 중 1개는 기존 40개 실행 시나리오이므로 추가 통합 시나리오는 32개.
- 화면 폭 320 / 375 / 390 / 768 / 1024px 확인. 한국 시간 기준과 미국 기기의 연초 날짜 확인.
- 초기 통합 시나리오 20개 중 13개 실패를 재현한 뒤 수정하고 통과 확인.

## 재현 후 수정한 문제

- 관리자 저장 함수 일부의 권한 재확인 누락. 로그인/로그아웃 시 등반·공지 버튼이 바로 갱신되지 않음.
- 얼리버드 선택 후 일반 전체 선택 시 두 그룹에 같은 학생이 남아 중복 적립됨.
- 출석 재등록·연속 클릭 시 중복 기록 생성. 병렬 저장 중 오류 시 일부 학생만 적립됨.
- 등반 완료 표시 후 학생 등록·보상 저장이 실패하면 복구 어려움. 등반일 출석 자동 적립 누락, 수동 전도 보상과 중복 가능.
- 스탬프에 동일 날짜를 반복 입력 가능.
- 전년도 점수가 올해 랭킹·프로필·정산 누적에 포함됨.
- 공지가 4개 이상이면 뒤의 공지로 이동할 페이지 버튼이 없음.
- 인도자 보상에서도 환영 카드가 생성되고 등반 공지와 중복 표시됨.
- 필터 결과가 0건일 때 CSV가 전체 기록을 내보냄. 쉼표·따옴표·수식 문자열 처리가 없음.
- 기타 활동에 소수를 입력하면 정수로 잘려 저장됨. 공지 내용의 HTML이 그대로 실행될 수 있음.
- 기존 중복·미래·평일 출석이 출석률을 부풀림.
- 여러 URL로 같은 모듈을 불러오는 구조와 import 캐시 갱신 누락.
- 학생 목록 갱신 시 일부 선택 목록과 화면이 갱신되지 않음.

## 배포 판단에 남은 확인

실제 Firestore Rules는 저장소에 없고 아직 제공되지 않아 검증하지 못했다. 앱은 Firebase Auth를 사용하지 않고 브라우저의 해시 비교와 전역 상태로 역할을 구분한다. 따라서 현재 DB가 관리자·교사를 서버에서 구분하거나 비인가 쓰기를 차단한다고 결론내릴 수 없다.

메모리 테스트는 실제 Firestore의 권한, 인덱스, 네트워크 지연, 트랜잭션 충돌 재시도를 대신 검증하지 않는다. 실제 휴대전화 Safari/Chrome 확인도 별도다. 학생의 기록이 400개를 초과하는 삭제는 여러 배치로 처리하므로 뒤 배치가 실패하면 앞 배치 삭제는 완료된 상태이며, 학생을 남겨 재시도할 수 있게 한다.

운영 데이터에 이미 존재하는 중복 포인트는 자동 삭제하지 않았다. 출석률 집계에서는 중복 날짜를 제외하지만 기존 포인트 정정은 실제 데이터 검토가 필요하다. 기존 수동 전도 보상이 일부만 지급된 사례도 운영 데이터 확인 후 처리해야 한다.

현재 push는 보류한다. 기존 커밋은 `feat:` / `fix:` 접두사와 한국어 한 줄 제목 형식이다. 최종 검증 후 사용할 제목: `fix: 권한별 기능 검증 및 중복 적립 방지, 모바일 UI 개선`.

배포본은 기존 코드 로그인을 유지한다. Firebase Auth/Rules 전환은 이번 배포에서 제외했다. 월별 카드·그래프 평균 일치 및 관리자/교사의 평일 일반·얼리버드 입력 차단을 추가 검증했다.
