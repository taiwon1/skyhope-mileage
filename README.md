## 🔐 관리자 모드 사용법

1. 우측 상단 **👁 읽기 전용** 배지 클릭
2. 관리자 비밀번호 입력
3. **🔑 관리자 모드** 전환 → 기록 입력 · 삭제 · 학생 관리 활성화

### 관리자 인증 관리

- 비밀번호는 SHA-256 해시값으로만 저장 (평문 없음)
- 로그인 시 입력값을 해싱한 뒤 저장된 해시와 비교
- isAdmin 상태를 전역(window.authState)으로 공유

### 비밀번호 변경 방법:

- 브라우저 콘솔에서 아래 실행 후 나온 해시값을 ADMIN_HASH에 붙여넣기

```
const b = new TextEncoder().encode('새비밀번호');
const h = await crypto.subtle.digest('SHA-256', b);
console.log([...new Uint8Array(h)].map(x=>x.toString(16).padStart(2,'0')).join(''));
```

## 운영 기준 (2026-09-14 확인)

- 마일리지는 매년 초기화하며, 연말 대면 행사에서 활용한다.
- 새친구는 4주 출석 후 등반할 때 본인과 인도자에게 각각 1,000P를 지급한다. 새친구 1명당 한 번만 지급하며, 인도자가 없으면 본인에게만 지급한다.
- 등반 전 1~3주차에는 출석 점수를 적립하지 않는다. 등반하는 4주차 출석일부터 적립한다.
- 개인 계정 없이 학생들이 서로의 출석 및 마일리지를 조회하는 공개 게시판 형태를 유지한다.
- 모바일 사용을 우선으로 가독성과 터치 편의성을 개선한다.

랭킹·프로필·정산 누적은 해당 연도만 집계하며 과거 기록은 보존한다. 등반은 학생 등록·환영 공지·전도 보상·등반일 일반 출석 100P를 한 트랜잭션으로 저장한다. 활동 입력의 수동 전도 보상은 차단하고, 기존에 지급한 전도 기록은 다시 지급하지 않는다. 새로 등반한 학생의 `mileageStartDate` 이전 활동은 등록할 수 없다.

## 테스트

`node tests/run-browser.cjs`로 실제 HTML/ES Module을 브라우저에서 실행하는 통합 테스트를 진행한다. Node.js, Playwright 및 Microsoft Edge가 필요하다. `TEST_BROWSER_CHANNEL`로 브라우저 채널을 바꿀 수 있고, `TEST_ARTIFACT_DIR`를 지정하면 모바일 검증 이미지를 저장한다.

테스트는 Firebase SDK 요청을 메모리 저장소로 대체하고 기타 외부 요청을 차단한다. 운영 DB에 기록을 만들거나 삭제하지 않는다. 실제 Firestore Rules 및 서버의 트랜잭션 충돌/재시도는 별도 검증이 필요하다. 상세 결과와 권한별 범위는 [테스트 보고서](tests/TEST_REPORT.md)를 참고한다.

배포 캐시 버전은 `index.html`과 `scripts/`의 모든 상대 모듈 import URL에 같은 값을 사용한다. 일부만 갱신하면 서로 다른 모듈 인스턴스가 생성될 수 있다.

출석 현황 화면은 교사·관리자 로그인에서만 제공한다. 로그인 유지 선택 시 해당 브라우저에 역할과 코드 버전 확인값을 저장하며, 로그아웃·브라우저 데이터 삭제·코드 변경 시 해제된다. 이 기능은 기존 코드 기반 화면 제어이며 서버 인증이나 Firestore 데이터 접근 제한을 추가하지 않는다.
